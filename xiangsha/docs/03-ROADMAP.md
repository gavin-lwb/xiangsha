## 附录 D · 我对评审报告的异议清单

> **说明**：以下是我对三份评审报告的异议，按议题编号。每条异议包含「评审员建议」「我的异议」「建议方案」三段。

### D.1 模块 B 替换方案：建议给用户二选一

- **评审员建议**（一号 / 三号）：替换为「喝啥」
- **二号建议**：v1 做成「轻量版点子库」30-50 张卡片
- **我的异议**：三个方案各有优劣，但文档未给用户二选一机会。我个人倾向**「喝啥」**（差异化更高），但**「点子库」** 工程量更小（复用现有字段和抽签引擎），如果时间紧是个合理备选。
- **建议方案**：默认「喝啥」，在拆分 SPEC.md 时让用户最终决定。**请用户在拆 SPEC.md 前确认**。

### D.2 拍照姿势 v1 用 emoji 还是线稿图

- **一号建议**：v1 emoji + SF Symbols 占位，v1.1 真实图库
- **二号建议**：v1 用线稿图（成本极低，体验强 100 倍）
- **三号建议**：未涉及
- **我的异议**：二号的线稿图方案**确实更优**，但需要设计资源（自绘或 CC0 素材），且 v1 开发周期可能不允许。我的折中：**v1 emoji + 详细文字引导 + 位置引导（D082-D084 已包含）**，**v1.1 加线稿图**，**v1.2+ 才上真人图**。分三步走而不是两步。
- **当前文档采用**：D077 已明确分三步（emoji → 线稿图 → 真人图）

### D.3 「决策反向解释 ❓」按钮（v1 vs v1.1）

- **三号建议**：v1.1 上线决策反向解释按钮
- **我的异议**：同意，但**默认隐藏**，**用户主动点 ❓ 才展示**。否则会增加每次抽签的认知负担（黑盒打破 → 信息过载）。
- **当前文档采用**：第 8 节未引入，v1.1 规划中明确「主动触发」

### D.4 Routine 一键三抽

- **一号建议**：v1 即做 Routine
- **二号建议**：v1 加「今日三签」首页
- **三号建议**：v1.1 做 Routine
- **我的异议**：**v1 不做 Routine，也不做独立「今日三签」首页**（会改 IA）。v1 只做基础联动（D121 已包含「跨模块推荐 Banner」），v1.1 再做完整 Routine + Banner 一键三抽。**用户首次启动的 IA 不要轻易改**。
- **当前文档采用**：第 9 节明确 v1 基础联动 + v1.1 Routine

### D.5 声景设计（三号独有）

- **三号建议**：v1 加环境音（锅底咕嘟声 / 海浪声 / 颂钵音）

### D.6 数据闭环（接受→完成→反馈）

- **二号建议**：v1 加 3 个按钮（做完了/没做成 + 评分）
- **三号建议**：支持
